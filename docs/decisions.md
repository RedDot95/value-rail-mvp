| D-01 | **Modularer Monolith** in Python (`src/value_rail/*`), ein Prozess pro Rolle (Web, Worker, CLI) auf derselben DB | Bauauftrag; minimaler Betriebsaufwand, klare Modulgrenzen für spätere Extraktion |
| D-02 | **Decimal überall für Geld**; Floats werden in Pydantic-Modellen (`BeforeValidator`) und DB-Typ (`DecimalText`) aktiv abgewiesen; fester Decimal-Kontext (prec 28, ROUND_HALF_EVEN) | Exakte, reproduzierbare Beträge; SQLite-NUMERIC würde über float runden → Decimal als TEXT gespeichert |
| D-03 | **UTC intern**, `UTCDateTime` speichert ISO-8601 mit `+00:00`, naive Datetimes werden abgelehnt; Anzeige in Europe/Berlin (Jinja-Filter `berlin`) | Bauauftrag; keine DST-Fehler |
| D-04 | **Unveränderliche Snapshots**: products, offer_snapshots, evidence, rule_versions, quotes, route_evaluations, execution_results. Korrekturen = neue Zeile mit `version+1`, `supersedes_id` | Audit-Fähigkeit; auch Roh-SQL kann nichts überschreiben |
| D-05 | **"unknown" statt null** für fehlende Pflichtinformationen (Preis, Währung, Mengen, Zeitstempel, Restkapazität, Ursache) | Bauauftrag; "unbekannt" ist eine Aussage, null wäre mehrdeutig |

| D-08 | **Statuspräzedenz**: harter Block (Identität, unbekannte Währung, unbekannte Pflichtgebühr, nur Aggregator-Preis) → `blocked`; vollständige frische Route über Schwellen → `verified_route` (unter Schwelle → `no_signal`); vollständige Route mit veraltetem Quote oder veraltetes Preisbasis-Angebot → `expired`; belegter Nominalrabatt ≥ Schwelle → `price_find`; sonst `no_signal` | Konservativ: ein Block schlägt jede positive Aussage |

| D-10 | **Bewertete Menge q = min(checkout-bestätigte Menge, belegte Exit-Tiefe)**; acquisition_cost(q) und net_exit(q) werden aus Stückpreis + Gebühren berechnet (fix/Order, fix/Stück, Prozent) | Fall 9; Gebühren skalieren korrekt; Monotonie (Fall 10) |
| D-11 | Gebühr mit `included_in_quote=true` wird nur als 0,00-Zeile dokumentiert, nie addiert; Angebot mit `price_includes_fees=true` addiert gelistete Gebühren nicht erneut | Keine Doppelgebühr (Fall 11) |
| D-12 | **Aggregatoren sind `discovery_only`**: ihre Preise sind nie Preisbasis; nur identische Direktangebote (alle 6 Identitätsfelder gleich, kein Feld "unknown") zählen. Nur-Aggregator → `blocked` | Fall 1 |
| D-13 | **Produktidentität** = Nennwert + Währung + Region + Variante + Seller + Einlöseprogramm; **Asset-Identität** = Chain + Contract (Ticker irrelevant, DB-Unique-Constraint) | Fälle 7, 8 |
| D-14 | **"$" allein ⇒ Währung unknown** (auch ¥, kr); nur eindeutige Marker (€, EUR, US$, USD, £ …) setzen eine Währung. Unbekannte Währung blockiert; bekannte Fremdwährung ohne FX-Kurs blockiert ebenfalls | Fall 6 |
| D-15 | **Replay**: `RouteInputs` enthält alles inkl. Bewertungszeitpunkt; gespeichert werden kanonisches Inputs-JSON, Inputs-Hash, Output-JSON, `rule_version_id`, `engine_version`. Regelversionen sind unveränderlich und über `valid_from` aktiv | Fall 16; exakte Reproduktion solange `engine_version` gleich ist (Code-Änderungen an der Engine erhöhen die Version) |

| D-42 | **Optionale Modell-Urteile als Enrichment-/Safety-Layer** (TypeSafe System One / Modell Jev, Paket `src/value_rail/judgments/`, Tabelle `offer_judgments`, Migration 0004). **Standardmäßig AUS** (`[enrichment] enabled = false`, `provider = "null"`): der `NullJudgmentProvider` antwortet ohne Netzwerk mit „abstain“; der echte Provider wird nur bei `enabled = true` **und** `provider = "typesafe"` **und** gesetztem `TYPESAFE_API_KEY` gebaut, der HTTP-Client erst beim ersten Aufruf (kein Netz beim Import). Vier Fragen je Angebot in **einem** Batch-Request (TypeSafe wertet unabhängige Fragen parallel aus): `restriction_risk` (Noul: Region-Lock außerhalb DE/EWR oder nicht erfüllbares KYC), `looks_like_block_page` (Noul: Bot-/CAPTCHA-/Fehler-/Leerseite statt Angebotsdaten – nur Erkennung), `classify_instrument` (Choice: bitsa | paysafecard | crypto_voucher | other_or_none – nur Hinweis), `select_face_value` (Choice über Code-extrahierte Kandidaten). **Regeln:** (1) Urteile sind **inferierte Hinweise**, getrennt von beobachteten Fakten gespeichert (Provider, Modell-ID, Frage, Antwort, Wahrscheinlichkeit/Konfidenz, Zeitstempel; append-only), beobachtete Felder werden nie überschrieben. (2) **Nie in die Geld-Mathematik**: `valuation/` bleibt unverändert und autoritativ; das Paket importiert weder Engine noch Alerts (statischer Test), Enrichment läuft im Scan **nach** dem Commit aller Bewertungen; Test: Bewertungen, Alerts, Snapshots byte-identisch mit Null- und Fake-Provider. (3) **Nie ein Alert**: Alerts entstehen ausschließlich über Engine → Policy → Outbox. (4) **„Select, don't generate“**: Code findet Zahlen per Regex und parst sie mit dem konservativen Preisparser zu `Decimal`; das Modell sieht nur Optionsschlüssel `candidate_<n>` (+ `none_or_uncertain`) und wählt einen aus; Code kopiert das bereits extrahierte `Decimal` (unbekannter Schlüssel, „none“, geringe Konfidenz ⇒ kein Wert). Eine vom Modell erzeugte Zahl wird nie zu einem Geldbetrag. (5) **Nur blockieren, nie freischalten**: `restriction_risk ≥ 0,8` ⇒ Signal `advisory_block` ⇒ Anzeige „Blockiert (inferred)“ neben dem unveränderten deterministischen Status (monotone Overlay-Funktion `judgments/safety.py`); `looks_like_block_page ≥ 0,8` ⇒ `suspected_block_page` (informativ in `/healthz` unter `inferred_last_24h`, ändert keinen Status). Kein Signal löst einen Retry, eine andere Route, einen Kauf, Checkout, Einlösung, Login oder eine Umgehung (CAPTCHA/Bot/Region/KYC, UA-Spoofing) aus. (6) **HTTP-API statt SDK**: Das offizielle `typesafe-sdk` (PyPI 0.7.2, 26.09.2026, gepflegt) bringt eigenen httpx2-Transport + tenacity-Retries mit und würde `net/http_safe.py` (Host-Allowlist, Public-IP-Pinning, keine Auto-Redirects, Body-Limit) umgehen sowie drei Laufzeitabhängigkeiten in den Stdlib-Netzwerkpfad (D-26) bringen. Die dokumentierte API ist ein Endpunkt (`POST /v1/systemone`, Bearer-Key) ⇒ direkter Aufruf über den neuen `SafeHttpClient.post_json_authorized` (nur https, folgt nie Redirects, Token-Syntaxprüfung, Token nie in Logs/request_log). Fehler/Timeout/429/529/ungültige Antwort ⇒ abstain + eine Warnzeile, nie eine Exception in den Scan. Budget: `max_requests_per_scan` (50), `max_questions_per_offer` (4, Safety-Fragen zuerst). Schwellen leben im Code/Config, nicht im Modell | Nutzerauftrag 06.10.2026; docs.typesafe.ai (siehe `docs/sources.md` §0c) |
